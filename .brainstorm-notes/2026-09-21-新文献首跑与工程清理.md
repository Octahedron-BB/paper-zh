### 操作要点（写给未来的自己）

- **音频读的是轨B，不是轨A**。`tools/build_audio.py` 只读 `data/script/<id>.json` 的 `script` 字段。
  轨A 是给你"读"的，轨B 是给你"听"的。
- **`--no-audio` 会连第 6 步 reader 一起跳过**（reader 必须内嵌 mp3）。
- `--stage reader` 会先跑 audio 再跑 reader；`--stage audio` 只跑 audio。
- 第 5 步会为每段单独存一份 mp3 + json（`data/audio/<id>/segments/`），最后拼接成整篇并生成 LRC/VTT。
- ⚠️ `--limit N` 试水会产出 `<id>_sample_<N>.mp3`，这不是独立文档（`src/docs.py` 已专门排除）。

## 四、修了什么

### 4.1 `slug()`：ASCII 标点与截断（`src/model.py`）

三条规则改动：

1. ASCII 标点折叠成 `-`，**不再转码点**（原实现把 `.` `,` 变成 `u002e` `u002c`）
2. 非 ASCII **仍然**转 `uXXXX` —— 中文标题只能靠它保存区分度，不能丢
3. 截断只在**完整原子边界**发生，且尽量收在连字符处

实测前后对比（都是真实标题）：

| 旧 | 新 |
|---|---|
| `non-antibiotic-drugsu002e` | `non-antibiotic-drugs` |
| `industrial-and-agricultural-chemicalsu00` | `industrial-and-agricultural-chemicals` |
| `evolution-of-antimicrobial-resistanceu00` | `evolution-of-antimicrobial-resistance` |
| `exploitation-of-bacterial-transport-syst` | `exploitation-of-bacterial-transport` |
| `medication-management-in-patients-with-t` | `medication-management-in-patients-with` |
| `colonu002c-rectal-and-anal-cancer` | `colon-rectal-and-anal-cancer` |
| `compoundu2013compound-interactions` | **不变**（en dash 是非 ASCII，必须保留） |

- 全仓库 `data/segments` 里原有 **176 处** `uXXXX`（`u002e` 108 / `u002c` 68），ASCII 标点造成的会全部消失。
- `SEGMENTER_VERSION`：`seg-v13-runinwrap` → **`seg-v14-slug-atomic`**（不 bump 就会静默复用旧 sec_path）
- 影响面已核实：`slug()` 的唯一调用点是 `src/segment.py` 的 `new_section()`；
  缓存键是 `src_hash` / 译文文本哈希，**不含 sid**，所以轨A/轨B 仍然全部命中，只有分段要重跑（免费）。
- 新增 3 条回归测试（其中"`uXXXX` 是不可分割的原子"那条的期望值全是**实测打印**出来的）。

### 4.2 去硬编码（8 处清单 → `src/docs.py`）

同一段"谁是谁"的逻辑原本被复制成 4 份硬编码清单，后果就是问题 2 那种静默漏检。
先抽了共用模块 `src/docs.py`（`pdf_ids` / `ids_with` / `read_field` / `processed_docs` / `resolve_doc_id`），
然后改了 8 处：

| 文件 | 原来 | 现在 |
|---|---|---|
| `tests/test_segment.py` | `CASES` 写死 4 篇 | 自动扫 `papers/*.pdf` |
| `tools/qa_report.py` | `DOCS` 写死 4 篇 | 自动扫 `data/translation/` |
| `devtools/audit_hard_landing.py` | `FIELDS` 写死 4 篇 | 同上 |
| `devtools/audit_term_density.py` | `FIELDS` 写死 4 篇 | 同上 |
| `tools/check_terms.py` | `DOC_ID`/`FIELD` 兼作默认值 | `--doc-id` 自动挑；`--field` 从 meta 读；原常量改名 `DEMO_*` 只服务演示段 |
| `tools/build_audio.py` | `--doc-id default="s41575-024-00932-1"` | `resolve_doc_id(stage="script")` |
| `tools/build_reader.py` | 同上 | `resolve_doc_id(stage="audio")` |
| `tools/run_pipeline.py` | `PDF_DEFAULT` 写死一篇 | 只有一篇就用它，多篇报错 |

**贯穿的原则换成：`--doc-id` / `--pdf` 忘传时，宁可报错也不猜。**
原来那些默认值指向另一篇文献，忘传就会对**错误的文档**静默跑完整个流程（不报错，只是结果全错）。

`tools/disambiguate.py`、`tools/build_interleave.py` 本来就是 `required=True`，没动。

**验证**：`run_pipeline.py` / `check_terms.py` 不带参数都会列出 5 篇候选；
`devtools/audit_term_density.py`、`qa_report.py` 都自动覆盖 5 篇。

### 4.3 🔴 去硬编码的**直接收益**：立刻抓到一个预先存在的 bug

## 五、术语表（新建 `glossary-d/s41575-026-01258-w.yaml`）

主表那 20 条是神经科学那篇的，本文一条都用不上，所以本文概念**全部落在 doc 级文件里**（32 条）：

| 组 | 条数 | 模式 | 理由 |
|---|---|---|---|
| 缩略语 | 6 | prompt_hint | NAA / SCFA / PFAS / NSAID / EPSPS / SHIME，要定首次出现格式；一律填 `full_en` |
| 近义术语 | 6 | prompt_hint | 本文靠这些区别立论：non-antibiotic compound / drug / NAA / xenobiotic 四者不能混；antimicrobial resistance ≠ antibiotic resistance；microbiome ≠ microbial community |
| 归一与清残留 | 20 | hard_replace | **零成本立刻生效**，按"能用字符串替换解决的绝不调 LLM" |

**干跑硬替换实测**（只改 8/51 段）：`外源物质` 3→0、`异生物质` 5→8、`H2S` 1→0、`硫化氢` 0→1、
`肠道微生物群` 1→0、`生物累积` 9→10；而 `菌群` 3 / `细菌群落` 2 **不变**（见下）。

### 两条血泪教训

1. **`aliases` 要写整段词组，不要写短子串。**
   我原本想把 `菌群` 当 `microbiome` 的别名统一掉。实测：中文译文里 3 处「菌群」有
   **2 处其实是「细菌群落」**（bacterial community，另一个概念）的子串 ——
   直接替换会得到「细菌微生物组」这种错词，**而且不报错**。
   剩下那 1 处才是真正的 microbiome 语境，为它去冒毁掉 2 处的风险不值得。
2. **统计口径要只数 `zh`。** 第一次我数在整个 JSON 文本上，而文件同时含 `src`/`zh`/`zh_raw`，
   数字**虚高一倍**，导致我把 `endobiotic` 的 2 处错误地当成"英文残留"写进 note（其实是英文原文里的）。
   已更正。凡是要说"某处有几处"，先打印、且打印**唯一口径**。

工具：新增 `scratch/mine_terms.py`（缩写频次表 + 高频二三元词组），以后给新文献补术语表先跑它。

## 六、❌ 未修：L1 标题跨行只取第二行（当前唯一红灯）

**证据**（PDF p10 第 110–111 行原文）：

```
Host implications of NAA–microbiome
interactions
```

真实标题跨两行，分段器把第二行 `interactions` 当成了完整标题，于是：

- `Section.heading` 变成小写的 `interactions`（触发 `test_headings_are_not_truncated`）
- `sec_path` 变成 `interactions/...`，子节路径里出现 `interactions/effect-on-treatment-outcome/...`

**为什么这个测试之前看不见它**：`CASES` 是硬编码的 4 篇。这正好印证了去硬编码的价值 ——
测试是好的，只是没被喂到这篇文献。

**修法建议**（尚未实施）：照 `_runin_head` 的向前回溯做法，把紧邻上方、同字号、
且**未完句**（不以 `.` `?` `!` 收尾）的行并入标题；然后 bump `SEGMENTER_VERSION` 重新分段，
并 `test_segment.py --update` 刷新基准。注意交叉验证 5 篇的标题都别被错误合并。

## 七、🔴 同一区域还发现两个未修的缺陷

1. **分段器会丢掉"没有直属段落"的节**。`src/segment.py::_build()` 末尾是
   `return [s for s in sections if s.segments]`。PDF p11 上真实存在的两个 L2 标题
   （`Effect on treatment outcome`、`Implication for antimicrobial resistance`）
   都不在 `doc.sections` 里，但它们的子节 `sec_path` 仍挂着这两个名字 ——
   所以会出现"子节路径的父级在 sections 里查不到"的状态。
   后果：伴读网页的章节目录少 2 个标题。
2. **两个标题被粘成一个**：出现 `Maintenancetreatment`（应为 `Maintenance` + `treatment`）。

## 八、本轮我犯的错（4 个，都记下来）

1. **统计口径错**：把整个 JSON 文本当译文数，虚高一倍，差点报出假结论（见五.2）。
2. **把期刊名猜错**：写成 Nature Reviews Urology，实际页眉是 Gastroenterology & Hepatology。
   → 教训：期刊名要**从 PDF 页眉读**，不要从 DOI 前缀猜。
3. **测试写错前提**：新增的"slug 全是完整原子"测试假设整个 slug 由转义组成，
   一跑就自己失败（`medication-management-in-patients-with` 里根本没有转义）。
   → 改成用**实测打印**出来的期望值。
4. **批量替换部分失败没及时发现**：`qa_report.py` 的导入块因空行数不符替换失败，
   但同一批里改 `main()` 的那条成功了 → 会 `NameError`。靠事后 `get_errors` + grep 残留才抓到。
   → 教训：批量替换后**必须复查每个改动点**，不能只看"文件已成功编辑"。
